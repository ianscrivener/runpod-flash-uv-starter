# What This Repo Does

A minimal **RunPod Flash** GPU worker project. It provisions a remote GPU on RunPod, runs a Python endpoint on it, and returns basic hardware diagnostics (`nvidia-smi` output and `/workspace` disk usage).

## High-Level Flow

```
Local machine                          RunPod Cloud
─────────────────                      ──────────────────────────────────
uv run main.py  ──── submits job ────► @Endpoint("gpu-info")
                                          runs nvidia-smi
                ◄─── returns result ──    runs du -sh /workspace
prints output
```

1. **Locally**: `main.py` loads config, resolves the target GPU group, and calls the decorated `hello()` function.
2. **Remotely**: RunPod Flash serialises and executes `hello()` on the configured GPU. The function shells out to `nvidia-smi` and `du` to confirm GPU visibility and available storage.
3. **Result**: The JSON response is returned to the local caller and printed.

The project also auto-generates a **local FastAPI dev server** (`.flash/server.py`) that mirrors the remote endpoint at `/main/runsync`, letting you test the worker logic without deploying to RunPod.

## Tech & Modules

| Layer | Technology |
|---|---|
| **GPU compute** | [RunPod Flash](https://github.com/runpod/runpod-flash) — serverless GPU workers with a Python-native `@Endpoint` decorator |
| **GPU hardware** | NVIDIA — GPU group selectable: `ADA_24`, `ADA_48`, `AMPERE_80` |
| **CUDA** | Minimum version `12.8` (configured in `config.yaml`) |
| **Local dev server** | FastAPI (auto-generated by Flash CLI in `.flash/server.py`) |
| **Config** | `config.yaml` — GPU group, worker count, volume size, CUDA version |
| **Secrets** | `python-dotenv` — loads `RUNPOD_API_KEY` from `.env` |
| **YAML parsing** | `pyyaml` |
| **Async runtime** | `asyncio` (Python stdlib) |
| **Package manager** | `uv` with `pyproject.toml` |

## Key Files

| File | Purpose |
|---|---|
| `main.py` | Local driver + remote `@Endpoint` definition |
| `config.yaml` | GPU, worker, and volume configuration |
| `.env` | RunPod API key (not committed) |
| `pyproject.toml` | Project metadata and dependencies |
| `.flash/server.py` | Auto-generated FastAPI dev server (do not edit) |

## Quick Start

```bash
uv sync
cp .env.example .env   # add RUNPOD_API_KEY
uv run main.py
```

## What It's a Seed For

Per the CLAUDE.md, this repo is a **seed/template** for a heavier pipeline that would:
- Download a Hugging Face model + calibration dataset in parallel
- AWQ-quantise it with `mlx_lm`
- Run a perplexity evaluation
- Render a model card from a Jinja2 template
- Push the quantised model back to the Hugging Face Hub

The current `main.py` is the proof-of-concept harness — just the GPU sanity check — before that full pipeline is wired in.
